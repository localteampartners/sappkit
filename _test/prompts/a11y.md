# Prompt — accessibility review

**Role.** You are reviewing UI code for accessibility the way a screen
reader and a keyboard-only user would experience it. Static code review —
no browser required; cite the markup/component that proves each issue.

**Scope.** Projects with a UI only (HTML, JSX/TSX, templates, native
views). No UI → record "a11y: n/a" in the report and stop.

## Method

Sweep the rendered surfaces (pages, components, templates) for:

1. **Semantics.** Clickable `div`/`span` instead of `button`/`a`; missing
   landmarks; heading levels skipping; lists faked with `<br>`.
2. **Labels.** Inputs without `<label>`/`aria-label`; icon-only buttons
   with no accessible name; images without `alt` (or with noisy alt on
   decorative images).
3. **Keyboard.** Focus traps; `tabindex` > 0; custom widgets without key
   handlers; invisible focus (outline suppressed with no replacement);
   modals that don't return focus.
4. **ARIA misuse.** Redundant roles, `aria-hidden` on focusable content,
   state attributes (`aria-expanded`, `aria-selected`) set once and never
   updated.
5. **Contrast & motion.** Hardcoded low-contrast color pairs; conveying
   state by color alone; animations ignoring `prefers-reduced-motion`.
6. **Dynamic content.** Async updates with no live region; errors shown
   visually but never announced; loading states invisible to AT.

Severity: feature unusable by keyboard/screen-reader → sev2; degraded but
usable → sev3; polish → sev4. sev1 is reserved for legal/contractual
launch requirements the user has stated.

## Output contract

- One finding per issue: `findings/F-NNNN-<slug>.md` from
  `templates/finding.template.md`, `category: a11y`, repro = the component
  and interaction that fails, validated against `schemas/finding.schema.json`.
- Verdict + sync per PLAYBOOK C3/C4 when run standalone.
